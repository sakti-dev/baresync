# Product

## Register

brand

## Users

Full-stack JavaScript developers evaluating Tauri for their next project. They're familiar with Node.js, Drizzle, and server-side frameworks like Hono or Express. They're looking at Baresync to solve the "local-first sync" problem without giving up control of their backend.

## Product Purpose

Baresync is SQLite-first sync infrastructure for Tauri apps. It gives developers a working sync engine (client, plugin, server helpers) from Drizzle schemas and a generated contract, so they can build offline-capable desktop apps without writing sync plumbing from scratch.

The docs and landing page serve as the entry point: explain what Baresync does, show how it works, and get developers to `bun create baresync@latest`.

## Brand Personality

Confident and direct. No fluff, no marketing buzzwords, no "seamless" or "revolutionary". Speaks like a senior engineer who knows the architecture and lets the design decisions speak for themselves.

## Anti-references

- Vercel's docs: too corporate, too much "enterprise-grade" energy
- Stripe's docs: beautiful but heavy, too much hand-holding for this audience
- Generic AI-generated SaaS landings: cream backgrounds, gradient text, identical card grids, numbered section eyebrows
- Any site that uses "revolutionary", "game-changing", "seamless", or "unleash" in copy

## Design Principles

1. **Show, don't tell.** Code snippets and architecture diagrams over marketing paragraphs. The product's value is obvious from the code.
2. **Opinionated by design.** Baresync makes specific architectural choices (server-wins, outbox pattern, Drizzle schemas). The docs should reflect that clarity, not hedge with "you can also..."
3. **Developer speed.** The landing page should feel fast. Minimal bloat, quick scans, get to the docs or the quick start in one scroll.
4. **Infrastructure, not a platform.** The docs are for a library, not a SaaS product. No pricing tables, no "book a demo", no hosted-service language.

## Accessibility & Inclusion

Standard WCAG AA. Code blocks should be readable. Motion should respect prefers-reduced-motion. No information conveyed by color alone.
