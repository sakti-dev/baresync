# Protobuf

Baresync supports two sync encodings: **JSON** (default) and **protobuf**. This section covers when protobuf makes sense and how to use it.

## Why protobuf

| Concern | JSON | Protobuf |
|---|---|---|
| **Payload size** | Larger — keys repeated per row, text-encoded numbers | 30–60% smaller — binary encoding, field numbers instead of keys |
| **Serialization speed** | Fast enough for most apps | Faster — no JSON parsing, no string escaping |
| **Schema evolution** | Flexible — new fields are ignored by default | Strict — field numbers must be stable across versions |
| **Debugging** | Human-readable in browser/network tools | Opaque binary — need the .proto to decode |
| **Ecosystem** | Universal — every language, every runtime | Requires proto runtime (prost in Rust, generated codec in TS) |

**Use protobuf when:**
- You have large sync payloads (hundreds of rows per cycle)
- You're on bandwidth-constrained networks (mobile, IoT)
- You control both sides of the wire and can manage schema evolution

**Stick with JSON when:**
- You're just getting started
- Your payloads are small (< 50 rows per sync)
- You want easy debugging with browser devtools
- You need to support third-party clients that don't speak protobuf

## Current support

Protobuf encoding currently works at the **server boundary** — the TypeScript server can accept and return protobuf-encoded sync requests. The generated artifacts include:

- A `.proto` schema definition
- A self-contained TypeScript binary codec (no protoc dependency)
- Rust `prost` struct definitions (for future Rust-side encoding)

The Rust sync engine currently sends **JSON over HTTP only**. Full protobuf transport from the Tauri plugin to the server is not yet implemented — it's on the roadmap. What works today:

```txt
✅ Server accepts protobuf requests (TS)
✅ Server returns protobuf responses (TS)
✅ Generated .proto file
✅ Generated TS binary codec (encode/decode)
✅ Generated Rust prost structs
✅ Server-side round-trip tests (JSON ↔ protobuf parity)

🔲 Tauri plugin sending protobuf over HTTP (not yet implemented)
🔲 Rust engine protobuf transport (not yet implemented)
```

## How it works

Protobuf in Baresync is opt-in and follows the same contract-first approach as JSON:

1. You define your sync contract with `defineProtobufSyncConfig()` instead of `defineSyncConfig()`
2. The generator produces protobuf-specific artifacts alongside the standard ones
3. Your server handlers receive an `encoding: "protobuf"` config with a `protobufSchema`
4. Requests and responses are binary-encoded using the generated codec

No `protoc` compiler is needed. The generated TypeScript runtime is a self-contained `BinaryWriter`/`BinaryReader` that handles encoding and decoding without external dependencies.
