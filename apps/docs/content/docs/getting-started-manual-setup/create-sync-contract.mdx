# Create the Sync Contract

The sync contract package is the bridge between your Tauri app and your server. Both import schemas from this single package so they always agree on table shapes, column names, and sync order.

## Why a separate package?

Your app needs to know the local table shapes (with outbox columns). Your server needs to know the API table shapes (with cursor columns). Both need the same table names, column names, and scope fields. Putting all of this in one shared package means you change a schema once and both sides update.

## Create the package

From your project root:

```bash
mkdir -p packages/sync-contract/src packages/sync-contract/generated
cd packages/sync-contract
bun init -y
bun add baresync drizzle-orm
```

## Write the constants

Create `packages/sync-contract/src/constants.ts`:

```ts
export const INVENTORY_SCOPE_ID = "default";
export const INVENTORY_PACKAGE_NAME = "inventory.sync.v1";
```

`INVENTORY_SCOPE_ID` is the scope your app syncs under. For this guide, every row belongs to the same scope. `INVENTORY_PACKAGE_NAME` is a dot-separated name that the generator uses to label the contract.

## Write the local synced schema

This defines the tables as they exist in the Tauri app's local SQLite database.

Create `packages/sync-contract/src/local-synced-schema.ts`:

```ts
import { localSyncColumns } from "baresync/schema";
import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

function createId() {
  return crypto.randomUUID();
}

export const locations = sqliteTable("locations", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => createId()),
  scopeId: text("scope_id").notNull(),
  name: text("name").notNull(),
  ...localSyncColumns(),
});

export const items = sqliteTable("items", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => createId()),
  scopeId: text("scope_id").notNull(),
  locationId: text("location_id").notNull(),
  name: text("name").notNull(),
  sku: text("sku"),
  ...localSyncColumns(),
});

export const stockCounts = sqliteTable("stock_counts", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => createId()),
  scopeId: text("scope_id").notNull(),
  itemId: text("item_id").notNull(),
  countedQuantity: integer("counted_quantity").notNull(),
  recordedAt: text("recorded_at").notNull(),
  ...localSyncColumns(),
});
```

Every synced table needs:

- `id` as `text` primary key
- A scope column (here `scopeId`) for partitioning data
- `...localSyncColumns()` which adds `deletedAt`, `isSynced`, `createdAt`, `updatedAt`

## Write the API synced schema

This defines the tables as they exist on your server.

Create `packages/sync-contract/src/api-synced-schema.ts`:

```ts
import { apiSyncColumns } from "baresync/schema";
import { index, integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const locations = sqliteTable(
  "locations",
  {
    id: text("id").primaryKey(),
    scopeId: text("scope_id").notNull(),
    name: text("name").notNull(),
    ...apiSyncColumns(),
  },
  (table) => [
    index("locations_scope_sync_idx").on(table.scopeId, table.syncUpdatedAt),
  ]
);

export const items = sqliteTable(
  "items",
  {
    id: text("id").primaryKey(),
    scopeId: text("scope_id").notNull(),
    locationId: text("location_id")
      .notNull()
      .references(() => locations.id),
    name: text("name").notNull(),
    sku: text("sku"),
    ...apiSyncColumns(),
  },
  (table) => [
    index("items_scope_sync_idx").on(table.scopeId, table.syncUpdatedAt),
    index("items_location_idx").on(table.locationId),
  ]
);

export const stockCounts = sqliteTable(
  "stock_counts",
  {
    id: text("id").primaryKey(),
    scopeId: text("scope_id").notNull(),
    itemId: text("item_id")
      .notNull()
      .references(() => items.id),
    countedQuantity: integer("counted_quantity").notNull(),
    recordedAt: text("recorded_at").notNull(),
    ...apiSyncColumns(),
  },
  (table) => [
    index("stock_counts_scope_sync_idx").on(table.scopeId, table.syncUpdatedAt),
    index("stock_counts_item_idx").on(table.itemId),
  ]
);
```

The API schema uses `...apiSyncColumns()` instead of `localSyncColumns()`. This adds `deletedAt`, `syncUpdatedAt`, `createdAt`, `updatedAt`. The `syncUpdatedAt` column is server-only — the server uses it as the cursor timestamp for incremental pulls.

Note the indexes on `(scopeId, syncUpdatedAt)`. These are important for pull performance. The generator does not create them automatically.

## Write the local runtime schema

The outbox and cursors tables live in the local database only.

Create `packages/sync-contract/src/local-schema.ts`:

```ts
import { createSyncCursorsTable, createSyncOutboxTable } from "baresync/schema";

export const syncOutbox = createSyncOutboxTable();
export const syncCursors = createSyncCursorsTable();
```

## Write the API runtime schema

The batch requests table lives on the server only.

Create `packages/sync-contract/src/api-schema.ts`:

```ts
import { createSyncBatchRequestsTable } from "baresync/schema";

export const syncBatchRequests = createSyncBatchRequestsTable();
```

## Write the sync config

The sync config tells the generator which tables to sync and where to output artifacts.

Create `packages/sync-contract/sync.config.ts`:

```ts
import { defineSyncConfig } from "baresync/generator";
import * as apiSyncedSchema from "./src/api-synced-schema";
import { INVENTORY_PACKAGE_NAME } from "./src/constants";
import * as localSyncedSchema from "./src/local-synced-schema";

export const syncGeneratorConfig = defineSyncConfig({
  apiSyncedSchema,
  localSyncedSchema,
  outputDir: "./generated",
  packageName: INVENTORY_PACKAGE_NAME,
  tables: {
    locations: { scopeColumn: "scope_id" },
    items: { scopeColumn: "scope_id" },
    stockCounts: { scopeColumn: "scope_id" },
  },
});
```

Each entry in `tables` maps a table name to its scope column. The generator uses this to produce the upsert and delete ordering.

## Configure package exports

Edit `packages/sync-contract/package.json`:

```json
{
  "name": "@repo/sync-contract",
  "private": true,
  "type": "module",
  "exports": {
    ".": "./src/constants.ts",
    "./constants": "./src/constants.ts",
    "./api-schema": "./src/api-schema.ts",
    "./api-synced-schema": "./src/api-synced-schema.ts",
    "./local-schema": "./src/local-schema.ts",
    "./local-synced-schema": "./src/local-synced-schema.ts",
    "./generated/sync-table-order": "./generated/sync-table-order.ts",
    "./generated/sync-contract": "./generated/sync-contract.json",
    "./generated/manifest": "./generated/sync-contract.manifest.json"
  },
  "scripts": {
    "generate": "bunx baresync generate",
    "typecheck": "bunx tsc -p tsconfig.json --noEmit"
  },
  "dependencies": {
    "baresync": "file:../../../path/to/packages/baresync",
    "drizzle-orm": "^0.45.2"
  },
  "devDependencies": {
    "typescript": "5.9.2"
  }
}
```

Adjust the `baresync` path to match your repo layout. In the Baresync repo itself, the inventory example uses `"file:../../../../packages/baresync"`.

## Run the generator

```bash
cd packages/sync-contract
bun run generate
```

This creates three files in `generated/`:

- `sync-contract.json` — the full contract with table columns, field numbers, limits, and scope mappings
- `sync-table-order.ts` — `SYNC_UPSERT_ORDER` and `SYNC_DELETE_ORDER` constants used by both the Rust plugin and the server
- `sync-contract.manifest.json` — a flat manifest for build tooling

## Verify

You should see:

```txt
packages/sync-contract/generated/
├── sync-contract.json
├── sync-contract.manifest.json
└── sync-table-order.ts
```
