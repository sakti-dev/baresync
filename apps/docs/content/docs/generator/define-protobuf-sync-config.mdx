# Define Protobuf Sync Config

If you want protobuf encoding instead of JSON, use `defineProtobufSyncConfig`.

## When to use protobuf

- Your sync payloads are large and you need smaller wire size
- You need strict schema evolution guarantees
- Your backend already uses protobuf

JSON is the default and simpler. Most apps do not need protobuf.

## The config

```ts
import { defineProtobufSyncConfig } from "baresync/generator";
import * as apiSyncedSchema from "./src/api-synced-schema";
import * as localSyncedSchema from "./src/local-synced-schema";

export const protobufSyncGeneratorConfig = defineProtobufSyncConfig({
  apiSyncedSchema,
  localSyncedSchema,
  outputDir: "./generated",
  packageName: "inventory.sync.v1",
  tables: {
    locations: { scope: "scope_id" },
    items: { scope: "scope_id" },
  },
  outputs: {
    protoDir: "./generated/proto",
    rustMapperDir: "./generated/rust",
    tsRuntimeDir: "./generated/ts",
  },
});
```

The `outputs` object tells the generator where to write protobuf-specific artifacts (`.proto` files, Rust mappers, TypeScript runtime code).

## Differences from JSON config

- `encoding` is automatically set to `"protobuf"`
- The `outputs` field is required
- Additional protobuf artifacts are generated alongside the standard ones

See [Protobuf](/docs/protobuf/overview) for details on the generated protobuf artifacts.
