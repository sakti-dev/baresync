# Runtime Tables

Baresync uses three runtime tables that are not synced themselves but support the sync engine. Use the factory functions from `baresync/schema` to create them.

## sync_outbox (local)

Tracks pending local changes that need to be pushed to the server.

| Column | Type | Purpose |
|---|---|---|
| `id` | `text` PK | UUID |
| `tableName` | `text` | Which table the change belongs to |
| `rowId` | `text` | Which row changed |
| `operation` | `text` | `"insert"`, `"update"`, or `"delete"` |
| `payload` | `text` (nullable) | Optional JSON payload |
| `scopeId` | `text` | Scope the change belongs to |
| `changedAt` | `text` | ISO timestamp of the change |
| `syncedAt` | `text` (nullable) | When the change was synced (null = pending) |

The table has a unique index on `(tableName, rowId) WHERE syncedAt IS NULL`. This means only one pending outbox entry per row. If you update the same row twice before sync, the outbox entry is upserted rather than duplicated.

This table lives in the **local app database** only.

## sync_cursors (local)

Stores the last cursor timestamp per scope so the client can do incremental pulls.

| Column | Type | Purpose |
|---|---|---|
| `id` | `integer` PK (auto) | Row ID |
| `scopeId` | `text` | Scope identifier |
| `lastCursor` | `text` | Last server watermark |
| `updatedAt` | `text` | When the cursor was last updated |

After a successful pull, the sync engine updates `lastCursor` to the highest `syncUpdatedAt` value from the pulled rows.

This table lives in the **local app database** only.

## sync_batch_requests (server)

Stores idempotency records for push requests on the server.

| Column | Type | Purpose |
|---|---|---|
| `id` | `integer` PK (auto) | Row ID |
| `clientId` | `text` | Client identifier |
| `idempotencyKey` | `text` | Unique key per push batch |
| `requestHash` | `text` | Hash of the request body |
| `status` | `text` | `"pending"`, `"completed"`, or `"failed"` |
| `responseBody` | `text` (nullable) | Cached response for replay |
| `createdAt` | `integer` | Unix timestamp |
| `completedAt` | `integer` (nullable) | When processing finished |

The table has a unique index on `(clientId, idempotencyKey)`. If a client retries a push with the same idempotency key, the server returns the cached response instead of processing it again.

This table lives in the **server database** only.

## Factory functions

Baresync provides factory functions that create Drizzle table definitions for the runtime tables. Use these in your sync contract package so both sides get the correct schema.

### createSyncOutboxTable

Creates the `sync_outbox` table with its unique index on pending rows.

```ts
import { createSyncOutboxTable } from "baresync/schema";

export const syncOutbox = createSyncOutboxTable();
```

### createSyncCursorsTable

Creates the `sync_cursors` table.

```ts
import { createSyncCursorsTable } from "baresync/schema";

export const syncCursors = createSyncCursorsTable();
```

### createSyncBatchRequestsTable

Creates the `sync_batch_requests` table with its idempotency index.

```ts
import { createSyncBatchRequestsTable } from "baresync/schema";

export const syncBatchRequests = createSyncBatchRequestsTable();
```

### Pre-built instances

Baresync also exports ready-made instances if you do not need to customize:

```ts
import { syncOutbox, syncCursors, syncBatchRequests } from "baresync/schema";
```

These are the same as calling the factory functions yourself. Use whichever style you prefer.

### Typical local-schema.ts

```ts
import { createSyncCursorsTable, createSyncOutboxTable } from "baresync/schema";

export const syncOutbox = createSyncOutboxTable();
export const syncCursors = createSyncCursorsTable();
```

### Typical api-schema.ts

```ts
import { createSyncBatchRequestsTable } from "baresync/schema";

export const syncBatchRequests = createSyncBatchRequestsTable();
```
