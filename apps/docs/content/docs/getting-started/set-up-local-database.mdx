# Set Up the Local Database

Your React code talks to SQLite through a Drizzle ORM proxy. The proxy serializes queries and sends them to the Tauri plugin via `invoke`. You never touch raw SQL in JavaScript.

## Create the database module

Create `apps/app/src/lib/db.ts`:

```ts
import {
  syncCursors,
  syncOutbox,
} from "@repo/sync-contract/local-schema";
import {
  items,
  locations,
  stockCounts,
} from "@repo/sync-contract/local-synced-schema";
import { invoke } from "@tauri-apps/api/core";
import { createTauriDrizzleDatabase } from "baresync/db";

export const TABLE = {
  items,
  locations,
  stockCounts,
  syncCursors,
  syncOutbox,
};

export const db = createTauriDrizzleDatabase({
  schema: TABLE,
  invoke,
});
```

Replace `@repo/sync-contract` with your actual package name.

## Why the TABLE registry?

`TABLE` collects all table references in one object. This makes queries explicit and avoids importing individual tables throughout your components:

```ts
// Instead of importing locations, items, stockCounts everywhere:
import { TABLE } from "./lib/db";

db.select().from(TABLE.locations);
```

It also ensures the Drizzle proxy knows about every table in your schema, including the runtime tables (`syncCursors`, `syncOutbox`).

## How createTauriDrizzleDatabase works

`createTauriDrizzleDatabase` creates a Drizzle `SQLiteProxyDatabase` that:

1. Serializes your Drizzle query builder calls into SQL
2. Sends the SQL to the Tauri plugin via `invoke("plugin:baresync|run_sql", { query })`
3. Returns the rows as plain objects

You use standard Drizzle query methods (`select`, `insert`, `update`, `delete`) and the proxy handles the transport.
