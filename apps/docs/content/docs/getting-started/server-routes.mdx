# Server Routes

The scaffold created three files that work together to handle sync requests from your Tauri app. The code below shows the Hono variant; if you chose Elysia during scaffolding, the structure is identical — only the router setup at the bottom of `routes.ts` differs.

- `apps/server/src/db/client.ts` — opens the server's SQLite database
- `apps/server/src/db/v1/sync-repository.ts` — reads and writes synced tables
- `apps/server/src/v1/routes.ts` — defines the `/api/v1/sync/{push,pull,status}` handlers

This page walks through each file so you know what to change when you add tables, swap databases, or wire up real authentication.

## Database connection

`apps/server/src/db/client.ts` opens a `better-sqlite3` connection and exports a `db` Drizzle instance:

```ts
import fs from "node:fs/promises";
import path from "node:path";
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";

const dbPath = path.resolve(
  process.cwd(),
  process.env.MY_APP_SERVER_DB_PATH ?? "./data/my-app-server.db"
);

await fs.mkdir(path.dirname(dbPath), { recursive: true });

const sqlite = new Database(dbPath);
sqlite.pragma("journal_mode = WAL");
sqlite.pragma("foreign_keys = ON");

export const db = drizzle(sqlite);
```

The database path defaults to `./data/<project-name>-server.db` and is overridable via the `<PROJECT_NAME>_SERVER_DB_PATH` environment variable. The data directory is created at scaffold time, so the file just opens the connection.

If you need a different driver (Postgres, MySQL, libSQL), replace the `drizzle()` call with the appropriate driver and update `apps/server/drizzle.config.ts` to match.

## Sync repository

`apps/server/src/db/v1/sync-repository.ts` wraps `createDrizzleSyncRepository` from `baresync/server/drizzle` with one entry per synced table:

```ts
import { lists, todos } from "@sync-contract/generated/<YYYY-MM-DD>/api-synced-schema";
import {
  createDrizzleSyncRepository,
  optionalString,
  requiredString,
} from "baresync/server/drizzle";
import { and, desc, eq, gt } from "drizzle-orm";

export function createAppSyncRepository(db) {
  const repository = createDrizzleSyncRepository({
    tables: {
      lists: {
        buildRow: ({ row, scopeId, syncUpdatedAt, updatedAt }) => ({
          createdAt: optionalString(row.createdAt) ?? updatedAt,
          deletedAt: optionalString(row.deletedAt),
          id: requiredString(row.id, "lists.id"),
          name: requiredString(row.name, "lists.name"),
          scopeId,
          syncUpdatedAt,
          updatedAt,
        }),
        readLatestRow: async ({ scopeId }) => {
          const rows = await db
            .select()
            .from(lists)
            .where(eq(lists.scopeId, scopeId))
            .orderBy(desc(lists.syncUpdatedAt), desc(lists.updatedAt), desc(lists.id))
            .limit(1);
          return rows[0] ?? null;
        },
        readRows: ({ cursorTimestamp, scopeId }) =>
          db
            .select()
            .from(lists)
            .where(
              cursorTimestamp > 0
                ? and(eq(lists.scopeId, scopeId), gt(lists.syncUpdatedAt, cursorTimestamp))
                : eq(lists.scopeId, scopeId)
            )
            .orderBy(desc(lists.syncUpdatedAt), desc(lists.updatedAt), desc(lists.id)),
        softDeleteRow: async ({ id, syncUpdatedAt, updatedAt }) => {
          await db.update(lists).set({ deletedAt: updatedAt, syncUpdatedAt, updatedAt }).where(eq(lists.id, id));
        },
        upsertRow: async (row) => {
          const { id: _id, ...setValues } = row;
          await db.insert(lists).values(row).onConflictDoUpdate({
            target: lists.id,
            set: setValues,
          });
        },
      },
      todos: {
        buildRow: ({ row, scopeId, syncUpdatedAt, updatedAt }) => ({
          createdAt: optionalString(row.createdAt) ?? updatedAt,
          deletedAt: optionalString(row.deletedAt),
          id: requiredString(row.id, "todos.id"),
          listId: requiredString(row.listId, "todos.listId"),
          title: requiredString(row.title, "todos.title"),
          scopeId,
          syncUpdatedAt,
          updatedAt,
        }),
        readLatestRow: async ({ scopeId }) => {
          const rows = await db
            .select()
            .from(todos)
            .where(eq(todos.scopeId, scopeId))
            .orderBy(desc(todos.syncUpdatedAt), desc(todos.updatedAt), desc(todos.id))
            .limit(1);
          return rows[0] ?? null;
        },
        readRows: ({ cursorTimestamp, scopeId }) =>
          db
            .select()
            .from(todos)
            .where(
              cursorTimestamp > 0
                ? and(eq(todos.scopeId, scopeId), gt(todos.syncUpdatedAt, cursorTimestamp))
                : eq(todos.scopeId, scopeId)
            )
            .orderBy(desc(todos.syncUpdatedAt), desc(todos.updatedAt), desc(todos.id)),
        softDeleteRow: async ({ id, syncUpdatedAt, updatedAt }) => {
          await db.update(todos).set({ deletedAt: updatedAt, syncUpdatedAt, updatedAt }).where(eq(todos.id, id));
        },
        upsertRow: async (row) => {
          const { id: _id, ...setValues } = row;
          await db.insert(todos).values(row).onConflictDoUpdate({
            target: todos.id,
            set: setValues,
          });
        },
      },
    },
  });

  return {
    tableNames: repository.tableNames,
    applyPushChanges: repository.applyPushChanges,
    loadPullChanges: repository.loadPullChanges,
    loadSyncStatus: repository.loadSyncStatus,
  };
}
```

Each table entry has:

- `buildRow` — constructs the API row from the raw push payload
- `readLatestRow` — returns the most recently updated row for cursor calculation
- `readRows` — returns all rows changed since a cursor timestamp
- `softDeleteRow` — marks a row as deleted
- `upsertRow` — inserts or updates a row

### Adding a new synced table

When you add a table to `packages/sync-contract/sync.config.ts` and regenerate the contract, you also need to add a corresponding entry here. The `buildRow` and `readRows` functions use the Drizzle table object imported from `@sync-contract/generated/<YYYY-MM-DD>/api-synced-schema`, so the import needs to include the new table too.

## Route handlers

`apps/server/src/v1/routes.ts` wires the three sync endpoints using `createSyncServer` from `baresync/server`. The example below shows the Hono variant; if you scaffolded with Elysia, the only difference is the router setup at the bottom of the file.
Pass the raw Web `Request` to `syncServer.push`, `syncServer.pull`, and `syncServer.status`. Avoid framework middleware that consumes the body before Baresync reads it, because push idempotency hashes the raw request bytes.

```ts
import { Hono } from "hono";
import { SYNC_SCOPE } from "@sync-contract/constants";
import { createSyncServer } from "baresync/server";
import { db } from "../db/client";
import { createAppSyncRepository } from "../db/v1/sync-repository";
const resolveScope = ({ scopeId }: { scopeId: string }) => {
  if (scopeId !== SYNC_SCOPE) {
    return {
      ok: false as const,
      status: 403,
      body: { error: "single_scope_only" },
    };
  }
  return {
    ok: true as const,
    scope: { scopeId },
  };
};
const repository = createAppSyncRepository(db);
const syncServer = createSyncServer({
  db,
  resolveScope,
  push: {
    upsertOrder: repository.tableNames,
    applyPushChanges: async ({ changes, scope, syncUpdatedAt }) =>
      repository.applyPushChanges({
        changes,
        scopeId: scope.scopeId,
        syncUpdatedAt,
      }),
  },
  pull: {
    limit: 1000,
    loadPullChanges: async ({ cursor, scope, tables }) =>
      repository.loadPullChanges({
        cursor,
        scopeId: scope.scopeId,
        tables,
      }),
  },
  status: {
    loadSyncStatus: async ({ cursor, scope }) =>
      repository.loadSyncStatus({
        cursor,
        scopeId: scope.scopeId,
      }),
  },
});
// Hono variant — mounts the handlers under /api/v1/sync at the index level.
const sync = new Hono();
sync.post("/push", (c) => syncServer.push(c.req.raw, {}));
sync.post("/pull", (c) => syncServer.pull(c.req.raw, {}));
sync.post("/status", (c) => syncServer.status(c.req.raw, {}));
export default sync;
```
`createSyncServer` is the batteries-included integration path. For custom protocol work, use the low-level primitives exported from `baresync/server`.
The handler factory handles body decoding, calls your `resolveScope`, and delegates to the repository functions. The route module is self-contained — it imports the database client and repository directly, so you only need to import it from `index.ts`.

### Customizing scope resolution

`resolveScope` is the one piece of business logic you need to replace. The scaffold's default accepts only the `SYNC_SCOPE` constant from your sync contract. In a real app, replace it with your auth check — verify the session token, look up the user, and return the scope they have access to:

```ts
const resolveScope = async ({ scopeId }: { scopeId: string }) => {
  const user = await getUserFromSession(request);
  if (!user || !user.scopes.includes(scopeId)) {
    return { ok: false as const, status: 403, body: { error: "forbidden" } };
  }
  return { ok: true as const, scope: { scopeId } };
};
```

The handler factories call `resolveScope` on every request. If it returns `{ ok: false, status, body }`, the handler returns that response immediately without touching the database.

## Mounting in index.ts

`apps/server/src/index.ts` mounts the route module under `/api/v1/sync`. The Hono variant:

```ts
import { Hono } from "hono";
import sync from "./v1/routes";

const app = new Hono();

app.get("/health", (c) => c.json({ ok: true }));
app.route("/api/v1/sync", sync);

export default app;

console.log(
  `my-app server listening on http://127.0.0.1:${process.env.PORT ?? "3001"}`
);
```

You typically don't need to touch this file. If you need to add middleware (CORS, request logging, rate limiting), add it before `app.route("/api/v1/sync", sync)`.
