# Commands

The plugin provides command logic and registers its own IPC handlers under the Tauri plugin namespace. Consumer apps usually only need to register the plugin itself with the builder.

## How commands work

The plugin registers the command implementations from `tauri_plugin_baresync::commands` inside `Builder::build()`. Tauri exposes those commands through the standard plugin namespace:

```txt
plugin:baresync|run_sql
plugin:baresync|sync_now
plugin:baresync|get_polling_status
```

Consumer apps that still have local wrappers can keep them temporarily and point the JS helpers at the older command names through override config.

## Command reference

### Database proxy

| Command | JS invoke | Description |
|---|---|---|
| `run_sql` | `"plugin:baresync|run_sql"` | Execute a single SQL query (select or run) |
| `run_sql_batch` | `"plugin:baresync|run_sql_batch"` | Execute multiple SQL statements in a transaction |
| `get_db_info` | `"plugin:baresync|get_db_info"` | Return database file path and size |

`run_sql` accepts a `SqlQuery { sql, params, method }`. When `method` is `"run"`, it returns no rows but reports `rows_affected`. When `method` is `"all"`, it returns rows.

`run_sql_batch` runs all statements in a single transaction. If any fails, the entire batch rolls back.

Both commands emit `baresync://data-changed` when `rows_affected > 0`. `run_sql` triggers an early sync only outside of transactions (uses transaction-depth tracking). `run_sql_batch` always triggers an early sync on success regardless of `rows_affected`.

### Migrations

| Command | JS invoke | Description |
|---|---|---|
| `run_migrations` | `"plugin:baresync|run_migrations"` | Re-run migrations manually (usually unnecessary) |
| `get_migration_status` | `"plugin:baresync|get_migration_status"` | List applied migrations with hashes |

Migrations run automatically during plugin setup. You only need `run_migrations` if you want to trigger them again at runtime (for example, after a hot update).

### Sync

| Command | JS invoke | Returns |
|---|---|---|
| `sync_now` | `"plugin:baresync|sync_now"` | `SyncNowResult` |
| `sync_push` | `"plugin:baresync|sync_push"` | `PushResult` |
| `sync_pull` | `"plugin:baresync|sync_pull"` | `PullResult` |
| `sync_full_resync` | `"plugin:baresync|sync_full_resync"` | `SyncNowResult` |
| `get_sync_local_state` | `"plugin:baresync|get_sync_local_state"` | `LocalSyncState` |

All sync commands take `scope_id: String`, except `purge_synced_outbox` which takes `older_than: String` (it operates across all scopes). See [Sync Commands](/docs/js-client/sync-commands) for the JS-side usage.

### Maintenance

| Command | JS invoke | Description |
|---|---|---|
| `purge_synced_outbox` | `"plugin:baresync|purge_synced_outbox"` | Delete synced outbox entries older than a timestamp |
| `run_garbage_collection` | `"plugin:baresync|run_garbage_collection"` | Remove soft-deleted rows that have been synced |

### Polling

| Command | JS invoke | Description |
|---|---|---|
| `start_polling` | `"plugin:baresync|start_polling"` | Start the polling loop for a scope |
| `stop_polling` | `"plugin:baresync|stop_polling"` | Stop the polling loop |
| `pause_polling` | `"plugin:baresync|pause_polling"` | Pause without stopping the timer |
| `resume_polling` | `"plugin:baresync|resume_polling"` | Resume from pause |
| `get_polling_status` | `"plugin:baresync|get_polling_status"` | Return running, paused, last_sync_at |

See [Polling](/docs/tauri-plugin/polling) for the polling lifecycle.

## Error handling

All commands return `Result<T, String>`. Errors are converted to strings with `.to_string()` before being sent back to JS. The JS client receives them as rejected promises.
