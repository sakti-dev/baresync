# Builder

The `Builder` constructs the Tauri plugin with your database path, server URL, generated contract metadata, migrations, and polling settings.

## Import

```rust
use tauri_plugin_baresync::builder::Builder as BaresyncBuilder;
```

## Basic usage

```rust
tauri::Builder::default()
    .plugin(
        BaresyncBuilder::new()
            .api_base_url("http://127.0.0.1:3001")
            .db_name("baresync.db")
            .contract_json(include_str!("../../../../packages/sync-contract/generated/sync-contract.json"))
            .migrations_path("migrations")
            .poll_interval_secs(30)
            .build(),
    )
    .run(generate_context!())
    .expect("failed to run app");
```

## Builder methods

| Method | Type | Required | Default | Description |
|---|---|---|---|---|
| `api_base_url` | `impl Into<String>` | Yes | `""` | Your server's base URL |
| `db_path` | `impl Into<String>` | No | `None` | Explicit path to the local SQLite file |
| `db_name` | `impl Into<String>` | No | `None` | Database file name resolved under the Tauri app data directory |
| `contract_tables` | `SyncContractTables` | No | empty | Upsert order, delete order, local-only columns |
| `contract_json` | `impl Into<String>` | No | `None` | Generated `sync-contract.json` metadata |
| `migrations` | `Vec<EmbeddedMigration>` | Yes | empty | Embedded SQL migrations |
| `migrations_path` | `impl Into<PathBuf>` | No | `None` | Path to `.sql` migrations bundled with the app or resolved absolutely |
| `poll_interval_secs` | `u64` | No | `30` | Seconds between polling cycles |
| `poll_on_background` | `bool` | No | `false` | Whether to poll when the window is unfocused |
| `max_push_bytes` | `usize` | No | `262144` | Maximum push payload size in bytes |
| `max_push_rows` | `usize` | No | `2000` | Maximum rows per push request |
| `transport` | `Arc<dyn SyncHttpTransport>` | No | `default_transport()` | Custom HTTP transport; optional for JSON apps and tests |

### api_base_url

The plugin uses this URL when making HTTP requests to your server. It is combined with the sync contract's endpoint paths.

### db_path

The SQLite file path. Use an environment variable to override for testing:

```rust
fn db_path() -> String {
    let base = env::var("MY_APP_DB_PATH").unwrap_or_else(|_| {
        let mut path = std::env::temp_dir();
        path.push("my-app.db");
        path.to_string_lossy().to_string()
    });
    PathBuf::from(base).to_string_lossy().to_string()
}
```

### contract_tables

Tells the plugin the order to insert/update and delete rows, and which columns are local-only:

```rust
fn contract_tables() -> SyncContractTables {
    SyncContractTables {
        upsert_order: vec![
            "locations".to_string(),
            "items".to_string(),
            "stock_counts".to_string(),
        ],
        delete_order: vec![
            "stock_counts".to_string(),
            "items".to_string(),
            "locations".to_string(),
        ],
        local_only_columns: vec!["is_synced".to_string()],
    }
}
```

These values come from your generated `sync-contract.json` or are supplied manually for tests and advanced integrations.

### db_name

Use `db_name` when you want the plugin to resolve the SQLite file under Tauri's app data directory:

```rust
BaresyncBuilder::new()
    .db_name("baresync.db")
```

This is the recommended default for production apps. Use `db_path` only when you need a deterministic path for tests or custom deployment environments.

### contract_json

Pass the generated `sync-contract.json` here to avoid duplicating table order and local-only column metadata in Rust:

```rust
BaresyncBuilder::new()
    .contract_json(include_str!("../../../../packages/sync-contract/generated/sync-contract.json"))
```

If you already have `SyncContractTables` in Rust, `contract_tables(...)` still works.

### migrations_path

Path-based migrations are the simplest production setup. Relative paths are resolved from the Tauri resource directory, so you can bundle a `migrations/` folder with your app and point the plugin at it:

```rust
BaresyncBuilder::new()
    .migrations_path("migrations")
```

See [Migrations](/docs/tauri-plugin/migrations) for the production and advanced migration options.

### migrations

Embedded migrations are compiled into the binary. Use this if you want the SQL stored in the Rust app instead of shipped as files:

```rust
include!(concat!(env!("OUT_DIR"), "/my_migrations.rs"));
```

### poll_on_background

When `false` (default), the plugin pauses polling when the window loses focus and resumes when it gains focus. This saves resources on desktop.

When `true`, polling continues regardless of window focus. Use this for background services or mobile apps where the webview lifecycle is managed differently.

On mobile, the plugin relies on app lifecycle and focus events exposed by Tauri. If your app needs background sync while unfocused, enable `poll_on_background` and verify that behavior on the target platform.

## What happens during setup

The builder's `setup` closure runs during Tauri initialization:

1. Resolves `db_path` or `db_name` and connects to SQLite (creates the file if missing, sets WAL mode, foreign keys on)
2. Runs `migrations_path` migrations in strict mode, if configured
3. Runs embedded migrations in strict mode, if no migration path is configured
4. Stores `PluginState` in Tauri's managed state

If any step fails, the app panics with a descriptive error.
