# Rust API

The Rust layer lives in two crates: `baresync-core` (engine, database, migrations) and `tauri-plugin-baresync` (Tauri integration).

---

## Plugin Builder

The builder configures and constructs the Tauri plugin. Used in your app's `lib.rs`.

```rust
use tauri_plugin_baresync::Builder;

Builder::new()
    .api_base_url("https://api.example.com")
    .encoding("json")
    .db_path("baresync.db")
    .encryption_key_provider(MyKeyProvider)
    .poll_interval_secs(30)
    .poll_on_background(false)
    .migrations_path("migrations")
    .contract_tables(SyncContractTables { upsert_order, delete_order, local_only_columns })
    .build()
```

### `Builder` methods

| Method | Type | Default | Description |
|---|---|---|---|
| `new()` | - | - | Create a new builder |
| `api_base_url(url)` | `impl Into<String>` | `""` | Server base URL |
| `encoding(enc)` | `impl Into<String>` | `"json"` | Wire format: `"json"` |
| `db_path(path)` | `impl Into<String>` | `"baresync.db"` | SQLite database file path |
| `encryption_key_provider(provider)` | `impl EncryptionKeyProvider` | - | App-owned raw 32-byte key provider used during setup |
| `max_push_bytes(n)` | `usize` | `262144` (256 KB) | Maximum push payload size |
| `max_push_rows(n)` | `usize` | `2000` | Maximum rows per push batch |
| `migrations(migs)` | `Vec<EmbeddedMigration>` | `[]` | Embedded SQL migrations |
| `migrations_path(path)` | `impl Into<PathBuf>` | - | Path to `.sql` migration files. Relative paths resolve from Tauri resources |
| `contract_tables(t)` | `SyncContractTables` | - | Table ordering and column config |
| `transport(t)` | `Arc<dyn SyncHttpTransport>` | `JsonHttpTransport` | Custom HTTP transport |
| `poll_interval_secs(n)` | `u64` | `30` | Seconds between automatic syncs |
| `poll_on_background(b)` | `bool` | `false` | Continue polling when app is backgrounded |
| `build()` | `TauriPlugin<R>` | - | Build the plugin |

If you configure `encryption_key_provider`, Baresync asks your app for a key during Rust setup before migrations run. The builder method is available in plaintext builds, but encrypted startup requires the `sqlcipher` Cargo feature. See [Database Encryption](/docs/local-database/encryption) for the full setup flow and failure cases.

### Encryption types

`DatabaseKey`, `EncryptionKeyContext`, and `EncryptionKeyProvider` are re-exported from `tauri_plugin_baresync` for convenience.

```rust
use std::error::Error;
use tauri_plugin_baresync::{DatabaseKey, EncryptionKeyContext, EncryptionKeyProvider};

struct MyKeyProvider;

impl EncryptionKeyProvider for MyKeyProvider {
    fn encryption_key(
        &self,
        context: EncryptionKeyContext,
    ) -> Result<DatabaseKey, Box<dyn Error + Send + Sync>> {
        let _db_path = context.db_path;
        let _database_exists = context.database_exists;
        Ok(DatabaseKey::from([0u8; 32]))
    }
}
```

## SyncEngine

The core sync engine. Created internally by the plugin — you don't construct it directly. Methods are exposed via [Tauri commands](/docs/reference/commands).

```rust
pub struct SyncEngine { /* private fields */ }
```

### Methods

| Method | Returns | Description |
|---|---|---|
| `new(db, config, tables)` | `Self` | Create engine with database client, config, and table ordering |
| `push()` | `Result<PushResult>` | Push local outbox to server |
| `pull(limit)` | `Result<PullResult>` | Pull server changes to local |
| `sync_now(limit)` | `Result<SyncNowResult>` | Intelligent sync — decides push/pull/full based on state |
| `sync_full_resync(limit)` | `Result<SyncNowResult>` | Drop cursor and re-sync from scratch |
| `get_sync_local_state()` | `Result<LocalSyncState>` | Dirty count, cursor, baseline flag |
| `purge_synced_outbox(older_than)` | `Result<u64>` | Delete synced outbox entries |
| `run_garbage_collection()` | `Result<usize>` | Remove soft-deleted synced rows |

### `SyncEngineConfig`

```rust
#[derive(Clone, Deserialize, Serialize)]
pub struct SyncEngineConfig {
    pub scope_id: String,
    pub api_url: String,
    pub client_id: String,
    pub encoding: String,
    pub target_push_bytes: usize,
    pub max_push_bytes: usize,
    pub max_push_rows: usize,
    pub transport: Arc<dyn SyncHttpTransport>,
}
```

Defaults: `encoding="json"`, `target_push_bytes=256KB`, `max_push_bytes=2MB`, `max_push_rows=2000`.

### `SyncNowMode`

```rust
pub enum SyncNowMode {
    NoOp,        // Nothing to sync
    PushOnly,    // Local changes need pushing
    PullOnly,    // Server has changes
    FullSync,    // Both sides have changes
    FullResync,  // Dropping cursor, re-syncing everything
}
```

### `SyncNowResult`

```rust
#[derive(Debug, Serialize)]
pub struct SyncNowResult {
    pub mode: SyncNowMode,
    pub status: Option<SyncStatusResult>,
    pub pull: Option<PullResult>,
    pub push: Option<PushResult>,
    pub purged: usize,
    pub skipped: Option<SyncNoOpResult>,
}
```

## HTTP Transport

```rust
pub trait SyncHttpTransport: Send + Sync {
    fn send_push_request(&self, api_url: String, envelope: Value) -> SyncTransportFuture;
    fn send_status_request(&self, api_url: String, body: Value) -> SyncTransportFuture;
    fn send_pull_request(&self, api_url: String, body: Value) -> SyncTransportFuture;
}
```

Default implementation: `JsonHttpTransport` — uses `reqwest` to POST JSON.

Endpoints:
- `POST {api_url}/sync/push`
- `POST {api_url}/sync/status`
- `POST {api_url}/sync/pull`

## Polling

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub struct PollingStatus {
    pub running: bool,
    pub paused: bool,
    pub last_sync_at: Option<String>,
}
```

The polling loop uses `tokio::select!` over three triggers:
1. **Timer** — interval-based (configurable via `poll_interval_secs`)
2. **Notify** — wakes on local writes (via `run_sql`/`run_sql_batch`)
3. **Control** — Pause/Resume/Stop/SyncCompleted messages

Auto-pauses on window unfocus unless `poll_on_background` is enabled.
