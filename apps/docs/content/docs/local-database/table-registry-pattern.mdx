# Table Registry Pattern

Baresync apps group all Drizzle table definitions into a single `TABLE` object. This object is used everywhere — the Drizzle proxy, the sync client, and your UI components.

## The pattern

```ts
import { items, locations } from "@your-app/sync-contract/local-synced-schema";
import { syncOutbox, syncCursors } from "@your-app/sync-contract/local-schema";

export const TABLE = {
  items,
  locations,
  syncOutbox,
  syncCursors,
};
```

Then pass it to `createTauriDrizzleDatabase`:

```ts
import { createTauriDrizzleDatabase } from "baresync/db";
import { invoke } from "@tauri-apps/api/core";

export const db = createTauriDrizzleDatabase({ schema: TABLE, invoke });
```

## Where TABLE is used

| Usage | How |
|---|---|
| Database creation | `createTauriDrizzleDatabase({ schema: TABLE, invoke })` |
| Queries | `db.select().from(TABLE.items)` |
| Writes | `client.writeLocalChange(tx, { table: TABLE.items, ... })` |
| Type inference | `type ItemRow = typeof TABLE.items.$inferSelect` |

## What goes in TABLE

### Synced tables (from your sync contract)

These are your business tables that sync with the server. They include `localSyncColumns()` (`isSynced`, `deletedAt`, `createdAt`, `updatedAt`).

```ts
import { items, locations } from "@your-app/sync-contract/local-synced-schema";
```

These are generated by the Baresync generator from your sync config. See [Generated Files](/docs/generator/generated-files).

### Baresync runtime tables

```ts
import { syncOutbox, syncCursors } from "@your-app/sync-contract/local-schema";
```

- `syncOutbox` — queues local writes for push
- `syncCursors` — stores the server cursor per scope

These are also generated. Including them in `TABLE` lets you query them for debugging.

### Local-only tables (optional)

If you have tables that don't sync but are used alongside synced data, add them too:

```ts
import { userPreferences } from "./local-tables";

export const TABLE = {
  items,
  locations,
  syncOutbox,
  syncCursors,
  userPreferences,
};
```

## Accessing table metadata

Drizzle exposes table metadata through `TABLE`:

```ts
// Infer the row type
type ItemRow = typeof TABLE.items.$inferSelect;

// Get the table name at runtime
import { getTableConfig } from "drizzle-orm/sqlite-core";
const config = getTableConfig(TABLE.items);
console.log(config.name); // "items"
```

## Why a single object

Drizzle's `sqlite-proxy` driver needs the full schema at creation time to produce correct SQL. By keeping everything in one `TABLE` object, you:

- Pass it once to `createTauriDrizzleDatabase`
- Import it in any component or hook
- Get type inference for free from Drizzle
